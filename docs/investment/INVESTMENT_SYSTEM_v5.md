## ⚙️ 미확정 파라미터 규칙 (코딩 에이전트 필독)

> 이 문서에는 리뷰 과정에서 *임의로 제안된* 숫자가 일부 들어 있었다. 그 값들은 근거가 없으므로, 확정값처럼 코드에 박아 넣으면 안 된다. 아래 마커가 붙은 값은 **반드시 구현 전에 사용자에게 질문해서 확정**한다.

```
🔧 사용자 정의 필요: <설명>
```

**코딩 에이전트 지침.**
- 위 마커를 만나면 코드를 작성하기 전에 멈추고, 해당 값을 사용자에게 직접 물어본다.
- 임의의 기본값을 추정해서 채워 넣지 않는다(예시로 적혀 있던 숫자도 쓰지 않는다).
- 사용자가 값을 정하기 전까지 코드 상수는 `None` 또는 `TODO`로 두고, 그 줄에 `# 🔧 사용자 정의 필요` 주석을 남긴다.
- §0 백테스트가 산출하는 값(손절폭·임계치 등)은 백테스트 결과로 채우는 것을 우선하되, 백테스트 전 단계라면 사용자에게 묻는다.

> 참고. v4에서 넘어온 점수표(§1·§3·§4의 배점·기준)는 사용자의 기존 설계값이므로 이 마커를 붙이지 않았다. 다만 이 값들도 §0 백테스트로 예측력을 검증한 뒤 확정하는 것이 원칙이다.

## 0. 과거 백테스트 ✅ 완료 (2026-06-07)

**목적:** 점수 가중치가 *느낌*이 아니라 *예측력*에 근거하도록 만든다. 이 단계를 건너뛰면 실제 계좌로 학습비를 내게 된다.

### 왜 필요한가

v4의 `backtest_log`는 사실 **포워드 페이퍼 로그**다. 앞으로의 결정을 기록할 뿐, "이 점수가 미래 수익률을 예측하긴 하는가"를 *사전에* 확인하지 못한다. 6개월 뒤에야 시스템의 쓸모를 알게 되며 그 기간은 곧 손실 위험이다.

### 검증 방법

```python
# 1. point-in-time 재구성이 쉬운 가격·모멘텀 팩터부터 검증
#    (RS, MA 정배열, 52주 위치, RSI)
# 2. 각 팩터 점수와 forward 3M/6M 수익률의 IC(정보계수) 측정
#    IC = spearman_corr(factor_score_t, return_t+horizon)
# 3. IC가 통계적으로 0과 구분되지 않는 항목 → 제거 또는 가중치 축소
# 4. 살아남은 팩터로 점수표 재구성 후에만 라이브 가동
```

### §0 최종 결과 (2018~2025, 성장 섹터 유니버스)

IC 합격 임계값 확정: **IC_THRESHOLD = 0.02**

| 팩터 | IC(12W) | t-stat | 판정 | screen.py 반영 |
|------|---------|--------|------|---------------|
| `rs_spy_6m` | +0.023 | 3.7 | **PASS** | RS 종합(+1) |
| `rs_qqq_6m` | +0.023 | 3.7 | **PASS** | RS 종합(+1, 통합) |
| `ma_alignment` | +0.021 | 3.9 | **PASS** | MA 정배열(+3/+1.5) |
| `week52_pos` | +0.031 | 4.4 | **PASS** | 52주 위치(+2/+1) |
| `rs_combined` | +0.019 | 3.7 | **WEAK_PENDING** | 가중치 낮춰 포함 |
| `rs_spy_1m/3m` | 미유의 | — | FAIL | 제외 |
| `rsi14` | -0.006 | 1.3 | FAIL | 극단 감점만 |

> RS SPY = RS QQQ 값이 완전히 동일 → 성장 섹터에서 상관 ≈1. v5 설계대로 **RS 종합 1개 항목**으로 통합 확정.
> 주요 인사이트: 단기 RS(1M/3M) FAIL, 6M RS PASS → 모멘텀은 6개월 이상 지속성이 핵심.

> ⚠️ **재무 팩터는 §0에서 검증이 거의 불가능하다.** 매출성장·FCF·기관보유율 같은 Fundamental Score 핵심 항목은 point-in-time 재무데이터를 개인이 구하기 어렵다. 따라서 §0를 통과해도 **시스템의 재무 절반은 미검증 상태로 출발**하며, 라이브 포워드 로그로 6개월 이상 누적해야 검증된다. 이 한계를 인지하고 초기엔 재무 팩터 가중치를 보수적으로 둔다.

## 1. Screen Score (`screen.py` 개선)

**목적:** "좋은 회사"를 찾는 1차 필터. 800종목 → 20종목.

| 항목 | 현재 | 변경 |
|------|------|------|
| Rule of 40 | 순이익률 사용 | **영업이익률(operatingMargins)으로 수정** |
| Gross Margin | 없음 | **신규 추가** |
| 시총 상한 | $15B | **$50B로 확장** |
| 기관보유율 | 없음 | **변화율(전분기 대비) 기준으로 추가** |
| RS | 없음 | **SPY · QQQ 각각 추가** |

| 부채비율 D/E | 최대 +2 | ≤0.3: +2 / ≤0.8: +1 / >2.0: -1 |

## 2. Deep Analysis + Conviction Band 🆕 v5

**목적:** "지금 살 회사인가?"의 정성 검증. LLM이 담당. 20종목 대상으로만 실행.

### 입력 데이터 (LLM에 전달)

```json
{
  "ticker": "RKLB",
  "business_summary": "소형 발사체 전문 우주기업...",
  "recent_news": ["NASA 계약 수주 $50M", "Neutron 개발 진척"],
  "revenue_growth": 34,
  "gross_margin": 31,
  "fcf": -120,
  "cash": 480,
  "cash_runway_quarters": 6,
  "major_customers": ["NASA", "DoD"],
  "competitors": ["SpaceX", "ULA"],
  "ceo": "Peter Beck",
  "insider_buying": "CEO +$2M (2026-03)",
  "analyst_estimates": {
    "next_q_revenue_growth": 38,
    "eps_revision_3m": "+25%"
  },
  "sector": "Space",
  "market_cap_b": 4.2
}
```

### LLM 출력 (전체 저장)

```json
{
  "business_quality":       8,
  "competitive_advantage":  9,
  "execution_risk":         4,
  "dilution_risk":          3,
  "tam_score":              9,

  "summary": "소형 발사체 시장에서 독점적 위치. NASA·DoD 장기 계약 기반 수익 가시성 높음. FCF 적자이나 현금 6분기 확보. 우주 민영화 핵심 수혜주.",

  "bull_case": [
    "Neutron 중형 로켓 개발 성공 시 시장 확장성 급증",
    "미 정부 우주 예산 증가로 장기 수주 파이프라인 견고",
    "발사 횟수 증가 → Gross Margin 구조적 개선 중"
  ],

  "bear_case": [
    "SpaceX Falcon 9 대비 가격 경쟁력 열위",
    "Neutron 개발 지연 시 희석 리스크 증가",
    "FCF 적자 지속 → 추가 자금조달 가능성"
  ],

  "key_risks": [
    "Neutron 개발 일정 지연",
    "정부 예산 삭감",
    "핵심 엔지니어 이탈"
  ]
}
```

### Conviction Band 산출 (v4의 정밀 점수 대체)

```python
raw = (
    business_quality +
    competitive_advantage +
    (10 - execution_risk) +
    (10 - dilution_risk) +
    tam_score
)   # 0~50

# 🆕 v5 정밀 점수(86 등) 대신 밴드로 받는다.
#    이유: LLM 출력은 재현성이 없어 8 vs 9 차이는 노이즈이고,
#          입력 프레이밍에 따라 흔들린다.
# 🔧 사용자 정의 필요: 상/중/하 밴드 경계값 (아래 38·28은 임의 제안값, 사용 금지)
BAND_HIGH = None   # 🔧 사용자 정의 필요: '상' 진입 raw 하한
BAND_MID  = None   # 🔧 사용자 정의 필요: '중' 진입 raw 하한 (이 미만은 '하' → 게이트 차단)
if   raw >= BAND_HIGH: band = "상"
elif raw >= BAND_MID:  band = "중"
else:                  band = "하"   # 게이트 차단
```

> 🆕 v5 **경계 수동 확인:** 밴드 경계(중↔하)에 걸린 종목은 사람이 직접 확인한 뒤 통과시킨다. 칼같은 자동 컷오프 금지.
>
> 🆕 v5 **확증 편향 차단:** 이미 정량 통과한 종목을 LLM에 주면 bull_case를 합리화하는 쪽으로 답이 치우친다. 프롬프트에서 bear_case·key_risks를 *먼저* 작성하게 강제하고, "이 종목을 사지 말아야 할 이유"를 별도 필드로 받는다.

## 5.5 시장 레짐 게이트 (매일) 🆕 v5

**목적:** 시스템에서 가장 위험한 구멍을 막는다. 유니버스가 전부 고멀티플 소형 성장주라 위험회피 장세에서 한 몸처럼 박살난다(2022년). 그런데 v4는 *절대적* 시장 상태를 전혀 보지 않았다.

> RS는 *상대* 강도다. 시장이 -30%일 때 -20%만 빠진 종목도 RS는 좋게 나온다. 즉 RS만 믿으면 베어장에 신규 매수가 나간다. 레짐 게이트는 이를 막는다. 단일 추가만으로 다른 어떤 팩터 튜닝보다 시스템을 크게 개선한다.

```python
# 매수 직전, 모든 종목에 공통 적용
# MA200 기준선 자체는 표준 레짐 판별법이라 고정.
spy_above_ma200 = SPY.close > SPY.ma200
qqq_above_ma200 = QQQ.close > QQQ.ma200

# 🔧 사용자 정의 필요: CAUTION 구간 사이즈 배율과 추가 점수 요구치
CAUTION_MULT       = None   # 🔧 사용자 정의 필요: CAUTION 시 사이즈 배율 (0~1)
CAUTION_SCORE_REQ  = None   # 🔧 사용자 정의 필요: CAUTION 시 Buy Score 추가 요구점수

if spy_above_ma200 and qqq_above_ma200:
    regime = "RISK_ON"      # 정상 사이징
    regime_mult = 1.0
elif spy_above_ma200 or qqq_above_ma200:
    regime = "CAUTION"      # 사이즈 축소 + 추가 점수 요구
    regime_mult = CAUTION_MULT
else:
    regime = "RISK_OFF"     # 신규 매수 차단 (기존 보유는 Exit 로직만 작동)
    regime_mult = 0.0

final_position = base_position × regime_mult
```

| 레짐 조건 | 신규 매수 | 사이징 |
|-----------|-----------|--------|
| SPY·QQQ 모두 MA200 위 | 정상 | × 1.0 |
| 하나만 위 | Buy Score 추가 요구 🔧 사용자 정의 필요 | × 🔧 사용자 정의 필요 |
| 둘 다 아래 | **차단** | × 0.0 |

> 옵션: VIX 급등 또는 SPY 단기 변동성 급등 시 추가로 사이즈 축소.
> 🔧 사용자 정의 필요: VIX 임계값·변동성 기준. 단, §0에서 효과 확인 후 도입.

## 8. Exit Score (가격 손절 + 펀더멘털) 🆕 v5

**목적:** "언제 팔까?" 시스템화. v4는 펀더멘털에만 기댔는데, 매출 둔화·FCF 전환·기관 감소는 전부 분기 단위 지연 데이터라 너무 느리다. IONQ 같은 변동성 종목은 펀더멘털 트리거가 켜지기 전에 가격이 -40% 간다. **텐배거 전략에서 전체를 무너뜨리는 건 늦은 손절이다.** 그래서 가격 손절을 펀더멘털과 분리해 매일 작동시킨다.

### [A] 가격 기반 손절 (매일, 펀더멘털과 독립) 🆕 v5

```python
# 펀더멘털 점수와 무관하게, 아래 중 하나라도 걸리면 즉시 신호
# 🔧 사용자 정의 필요: 손절 파라미터 4개 (아래 0.75·1.5·0.70은 임의 제안값, 사용 금지)
HARD_STOP_PCT     = None   # 🔧 사용자 정의 필요: 진입가 대비 하드 스톱 비율 (예: -25%면 0.75)
MA50_VOL_MULT     = None   # 🔧 사용자 정의 필요: MA50 이탈 시 거래량 배수 기준
TRAILING_STOP_PCT = None   # 🔧 사용자 정의 필요: 고점 대비 트레일링 스톱 비율 (예: -30%면 0.70)

stop_triggers = [
    entry_price * HARD_STOP_PCT >= close,             # 진입가 대비 하드 스톱
    close < ma50 and volume > avg_vol * MA50_VOL_MULT, # 거래량 동반 MA50 이탈
    close < trailing_high * TRAILING_STOP_PCT,         # 고점 대비 트레일링
]
if any(stop_triggers):
    signal = "PRICE_STOP"   # 즉시 매도 검토, 펀더멘털 누적과 별개
```

> 손절폭은 §0 백테스트로 종목 변동성에 맞춰 보정하는 것이 원칙이다. ATR 기반 스톱도 후보다. 변동성이 큰 종목(IONQ 등)에 좁은 손절을 쓰면 정상 등락에도 털리고, 차분한 종목에 넓은 손절을 쓰면 늦는다. 즉 종목별 변동성을 반영해 사용자가 확정한다. 핵심은 *펀더멘털 신호를 기다리지 않는다*는 것.

### [B] 펀더멘털 악화 (주 1회 누적 감점)

| 조건 | 감점 |
|------|------|
| 매출 성장 전분기 대비 -10%p 이상 둔화 | -3 |
| Gross Margin -5%p 이상 악화 | -2 |
| FCF 흑자→적자 전환 | -2 |
| 기관보유율 -10%p 이상 감소 | -2 |
| Dataroma 슈퍼인베스터 매도 | -2 |
| RS 6개월 SPY·QQQ 모두 마이너스 전환 | -2 |
| CEO 교체 | -5 |
| CFO 교체 | -4 |
| CFO 교체 + 유상증자 동시 발생 | **-8** |

### [C] 밸류에이션 과열

| 조건 | 처리 |
|------|------|
| Forward P/S > 40 | -3 |
| 현재 P/S > 5년 평균 3배 | -2 |
| RS 1개월 +50% 이상 | ⚠️ 경고 플래그만 (감점 없음, 텐배거 과정에서 정상) |

### 판정

```
[A] 가격 손절 발동      → 🚨 즉시 매도 검토 (펀더멘털 누적과 독립)
[B]+[C] 누적 -5 이하   → ⚠️ Exit Review 알림 + Backtest 로그 갱신
[B]+[C] 누적 -10 이하  → 🚨 강력 매도 신호
```
